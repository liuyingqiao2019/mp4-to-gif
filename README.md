# Frame GIF · 本地 MP4 转 GIF

需要 Node.js 20+。运行 `npm start`，打开 http://127.0.0.1:3815 。也可双击 `启动.cmd`。无需 npm 依赖，当前目录的 `bin/` 已放入本机现有的 FFmpeg 4.3.2 与 ffprobe，可离线转换。
迁移到其他电脑时需自行提供 FFmpeg / ffprobe 到 `bin/`，或设置 `FFMPEG_PATH` / `FFPROBE_PATH` 环境变量。当前二进制来自本机 GPT-SoVITS runtime；再次分发时应遵循对应 FFmpeg 构建的许可证。该构建支持常用 MP4 解码和 GIF 编码，但不保证所有新编码格式都能解码。
启动服务后可运行 `npm test` 验证实际转换、尺寸、帧数、大小上限、未达标、自动降帧与取消。

## 策略
- 保留原始像素尺寸，不使用 scale。带旋转信息的视频会自动校正方向，宽高可能互换。
- 独立设置 1–50 FPS。GIF 帧间隔精度为 1/100 秒，部分帧率有取整误差。
- 无论是否设置 MB，每帧均独立生成最多 256 色的调色板，保留 Sierra 误差扩散抖动；不使用全局调色板牺牲少见场景颜色。
- 指定上限时只尝试降低帧率，不减少颜色、不切换低质量抖动。逐次测量真实字节数，严格小于上限才判定达标。1 MB = 1,000,000 字节。
- 默认勾选允许降帧；取消勾选则严格保持帧率。降到 1 FPS 仍超出目标时提示未达标，不缩小宽高、不截短视频。
- 无法达标时明确标注并返回本轮最小结果。有限搜索不保证理论最优；GIF 每帧最多 256 色，仍不能保证视频色彩完全无损。
- palettegen stats_mode=single / paletteuse new=1，每帧独立调色板，reserve_transparent=0 为可见颜色保留完整 256 色预算。

## 上传网站与部署
网页选择/拖入视频后上传到运行服务的服务器，流式写入磁盘，不将整个上传文件放在 Node 内存中。默认本机监听；设置 `HOST=0.0.0.0` 可供其他设备访问，`PORT` 默认 3815。每次一个任务，忙时提示重试，输入上限 1 GB，上传超时 10 分钟，转换超时 25 分钟。

Linux 服务器安装 Docker 后，在项目目录运行 `docker compose up -d --build`。访问服务器的 3815 端口。容器使用系统 FFmpeg，不依赖 Windows 的 bin 目录；Compose 限制 2 GB 内存和 2 CPU。高分辨率长片段可能触发内存限制，需按服务器资源调整。

使用域名和 HTTPS 时在项目 `.env` 中设置 `PUBLIC_ORIGIN=https://你的域名`，通过反向代理指向 3815，并配置上传上限至少 1 GB、上传读取超时 600 秒。此版本是单实例、单转换槽的轻量网站，未提供账号、付费和任务队列。大规模使用需增加配额和排队。

## 自动清理
- 每隔 30 分钟清理所有已结束任务的文件和内存任务记录，结果保留至下一轮清理，不保证每份文件都有完整 30 分钟。
- 上传原文件在转换完成、失败或取消后立即删除，临时候选 GIF 同时删除。
- 清理跳过正在上传、转换和下载的任务；跳过的任务在后续周期处理。
- 服务启动时清理上次遗留的 UUID 任务目录，不删除其他目录。
- 页面提示清理时间，结果过期后接口返回 410，需要重新上传。
- 清理解决的是磁盘积累；转换内存由并发限制及容器内存上限控制。

执行 `node --test cleanup.test.mjs` 验证清理策略；启动服务后执行 `npm test` 验证转换。
